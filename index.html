1. Redes de Computadores

Conceitos e topologias

LAN (local), MAN (metropolitana) e WAN (longa distância). No modelo cliente/servidor, o cliente pede um serviço (ex.: o navegador) e o servidor responde (ex.: o site). Topologia é a forma como os dispositivos se ligam:

  • Barramento: um cabo único; barato, mas uma falha no cabo derruba a rede.
  • Estrela: tudo ligado a um switch central; a mais usada hoje; fácil de manter, mas depende do ponto central.
  • Anel: cada máquina liga à próxima, formando um círculo.
  • Malha: vários caminhos entre os nós; alta confiabilidade e custo maior.

Endereçamento e serviços

  • Endereço IP: identifica o dispositivo (ex.: 192.168.1.10).
  • Máscara de sub-rede: separa a parte da rede da parte do dispositivo (ex.: 255.255.255.0, ou /24).
  • Gateway: a “saída” da rede, em geral o roteador (ex.: 192.168.1.1).
  • DNS: traduz nomes em IPs (www.site.com → 203.0.113.5).
  • DHCP: distribui IPs automaticamente aos dispositivos.

Cabeamento e crimpagem

O conector RJ-45 recebe os 8 fios do cabo UTP, na ordem de um dos padrões:

  • T568A: branco/verde, verde, branco/laranja, azul, branco/azul, laranja, branco/marrom, marrom.
  • T568B: branco/laranja, laranja, branco/verde, azul, branco/azul, verde, branco/marrom, marrom.
  • Cabo direto: mesmo padrão nas duas pontas (liga computador a switch/roteador).
  • Crossover: A numa ponta e B na outra (liga dois equipamentos iguais, como PC com PC).

Crimpar: 1) desencape cerca de 2 cm da capa; 2) separe os pares e alinhe os fios na ordem escolhida; 3) corte as pontas rente; 4) insira até o fundo no RJ-45 (os fios devem encostar na ponta); 5) crimpe com o alicate; 6) repita na outra ponta; 7) teste no testador de cabos: as 8 luzes acendem em sequência nas duas unidades.

Provedor, manutenção e diagnóstico

A conexão com o ISP pode ser por fibra, cabo, rádio ou redes móveis (4G/5G).

Isolar por camadas (de baixo para cima): 1) cabo conectado e luzes do equipamento acesas? 2) ipconfig (Windows) ou ip a (Linux) mostram IP válido? 3) ping 192.168.1.1 responde (gateway)? 4) ping 8.8.8.8 responde (Internet)? 5) ping www.site.com responde (DNS)? Onde o teste falhar, está o problema.

Configurar IP manualmente (Windows): Configurações de rede → propriedades do adaptador → IPv4 → informe IP, máscara, gateway e DNS.

2. Design

Imagem digital

Pixel é o menor ponto de uma imagem; resolução é a quantidade de pixels (ex.: 1920 × 1080).

Modos de cor: RGB (vermelho, verde e azul; luz, usado em telas) × CMYK (ciano, magenta, amarelo e preto; tinta, usado em impressão).

Teoria das cores, tipografia e composição

  • Círculo cromático: organiza as cores. Complementares ficam opostas (azul e laranja) e geram forte contraste; análogas ficam vizinhas (azul, ciano, verde) e geram harmonia.
  • Contraste: diferença entre texto e fundo; garante leitura (importante para acessibilidade).
  • Tipografia: fontes com serifa (têm “pezinhos”, ex.: Times, Georgia) × sem serifa (ex.: Arial, Verdana). Hierarquia: títulos maiores e mais fortes que o texto.
  • Composição e grid: o grid (grade de colunas) alinha os elementos; a regra dos terços divide o quadro em 3 × 3 e posiciona o foco nas interseções.

Edição e exportação

Em editores como GIMP ou Photoshop: camadas (elementos sobrepostos editáveis separadamente), seleção e recorte, filtros e retoques (brilho, contraste, saturação, clone).

  • JPG: fotografias; compacta bem, mas não tem transparência.
  • PNG: transparência e nitidez (logotipos, capturas de tela).
  • GIF: animações simples, até 256 cores.
  • Otimização: reduza as dimensões ao tamanho de exibição e ajuste a qualidade; arquivos leves carregam mais rápido.

Wireframe, protótipo e leiaute

Wireframe é o esboço da estrutura da página, sem cores nem imagens finais. Protótipo interativo simula a navegação (ex.: Figma). Leiaute é a versão visual com cores, fontes e imagens.

3. Gerenciador de Conteúdo / Banco de Dados

Hospedagem, domínio e publicação

  • Hospedagem compartilhada: vários sites no mesmo servidor; barata, desempenho limitado.
  • VPS: parte dedicada de um servidor, com mais controle.
  • Nuvem: recursos escaláveis, pagos por uso.
  • Domínio: o nome do site (ex.: minhaescola.com.br), registrado e renovado periodicamente (no Brasil, o .br é registrado em registro.br).
  • Publicação: envio dos arquivos ao servidor por FTP (ex.: FileZilla) ou pelo painel da hospedagem.

CMS e WordPress

CMS permite criar e gerir sites sem programar tudo do zero. Instalação do WordPress: 1) crie um banco de dados e um usuário; 2) envie os arquivos ao servidor; 3) acesse o endereço do site e preencha os dados do banco; 4) crie o administrador. Depois, entre em /wp-admin.

  • Temas (templates): definem a aparência (Aparência → Temas).
  • Plugins: acrescentam funções (formulários, SEO, segurança).
  • Páginas (conteúdo fixo: Sobre, Contato) × posts (conteúdo em ordem cronológica, com categorias: notícias, blog).
  • Customização: logotipo, cores, menus e widgets.

phpMyAdmin, backup e SQL

O phpMyAdmin é uma interface web para gerir o MySQL: criar bancos e tabelas, executar SQL, importar e exportar (aba Exportar gera um arquivo .sql, o backup; para restaurar, use Importar). Faça backup do banco e dos arquivos do site.

CREATE TABLE alunos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(80) NOT NULL,
  nota DECIMAL(4,2)
);
INSERT INTO alunos (nome, nota) VALUES ('Ana', 8.5), ('Bruno', 6.0);
SELECT * FROM alunos;
SELECT nome FROM alunos WHERE nota >= 7 ORDER BY nome;
UPDATE alunos SET nota = 7.0 WHERE id = 2;
DELETE FROM alunos WHERE id = 2;

WHERE filtra linhas; ORDER BY ordena. Cuidado: UPDATE ou DELETE sem WHERE afeta a tabela inteira.

4. Programação Web II (PHP / MySQL)

Front-end, back-end e APIs

O back-end local roda no computador do desenvolvedor (ex.: XAMPP); o remoto, em um servidor na Internet. O front-end conversa com o back-end por APIs web:

  • REST: usa os métodos HTTP (GET, POST, PUT, DELETE) e, geralmente, JSON.
  • SOAP: protocolo mais rígido, usa XML.
// Resposta JSON de GET /api/alunos/1
{ "id": 1, "nome": "Ana", "nota": 8.5 }

// No front-end
fetch("/api/alunos/1").then(r => r.json()).then(a => console.log(a.nome));

Funções em PHP reaproveitam código: function media($a, $b) { return ($a + $b) / 2; }. Procedimentos executam ações sem devolver valor.

Sessões e cookies

  • Sessão (session_start(), $_SESSION): dados guardados no servidor; mais segura (o navegador guarda só o identificador).
  • Cookie: dados guardados no navegador; podem ser lidos e alterados pelo usuário.
<?php // login.php
session_start();
$con = new mysqli("localhost","root","","escola");
$st = $con->prepare("SELECT id, senha FROM usuarios WHERE email = ?");
$st->bind_param("s", $_POST["email"]);
$st->execute();
$u = $st->get_result()->fetch_assoc();
if ($u && password_verify($_POST["senha"], $u["senha"])) {
    $_SESSION["usuario_id"] = $u["id"];
    header("Location: painel.php"); exit;
}
echo "E-mail ou senha incorretos.";

// painel.php (página protegida)
session_start();
if (!isset($_SESSION["usuario_id"])) { header("Location: login.php"); exit; }

Guarde senhas com password_hash() e confira com password_verify(), nunca em texto puro.

SQL Injection

Ataque em que comandos SQL são inseridos num campo do formulário. Código vulnerável: "SELECT * FROM usuarios WHERE email = '$email'". Se o atacante digitar ' OR '1'='1, a condição vira sempre verdadeira e ele entra sem senha. Com consulta parametrizada, o valor é tratado só como dado, nunca como comando.

Questão de treino 13. A melhor prevenção contra SQL Injection é: a) concatenar o texto direto no SQL b) usar consultas parametrizadas c) esconder o formulário d) usar apenas cookies
Ver respostab) consultas parametrizadas.

5. Laboratório de Hardware

Segurança e ferramentas

  • Desligue o equipamento e desconecte da tomada antes de abrir.
  • Use pulseira antiestática presa a uma parte metálica do gabinete (aterramento) para evitar a descarga eletrostática (ESD), que pode queimar componentes sem sinal visível.
  • Mantenha a bancada organizada, seca e iluminada; guarde parafusos em recipiente.
  • Ferramentas: chaves de fenda e Phillips, alicate, multímetro.

Multímetro: fonte e continuidade

Com a fonte ligada à rede (e ao pino PS-ON em verde, no teste fora do PC), meça com o multímetro em tensão contínua (V DC): vermelho = +5 V, laranja = +3,3 V, amarelo = +12 V, em relação ao preto (terra). A norma ATX admite variação de cerca de ±5%:

FioNominalFaixa aceitável
Laranja3,3 V3,14 a 3,47 V
Vermelho5 V4,75 a 5,25 V
Amarelo12 V11,4 a 12,6 V

Continuidade: desligado e sem energia, coloque as ponteiras nas duas pontas do cabo; o bipe indica fio íntegro.

Montagem, desmontagem e diagnóstico

  • Memória: alinhe o chanfro do pente com o slot e pressione até os clipes travarem.
  • Placas (PCIe): encaixe no slot e prenda com parafuso no gabinete.
  • Discos: fixe na baia, ligue cabo de dados (SATA) e de energia; M.2 vai direto na placa-mãe.
  • Desmontagem: ordem inversa; tire fotos dos cabos antes de soltar.

Diagnóstico: o POST (Power-On Self Test) é o autoteste feito ao ligar. Se falhar, a placa emite beeps (o significado varia conforme o fabricante da BIOS, consulte o manual). Verifique também luzes e conectores soltos. O teste por troca de peças substitui uma peça suspeita por outra sabidamente boa; se o defeito some, a peça trocada era a causa. Troque uma de cada vez.

6. Laboratório de Software

Backup, imagem e recuperação

  • Backup completo: copia tudo. Incremental: copia só o que mudou desde o último backup (qualquer tipo). Diferencial: copia o que mudou desde o último completo.
  • Imagem do sistema: cópia exata da partição (SO, programas e configurações) que permite restaurar a máquina inteira.
  • Recuperação de desastres: mídia de recuperação, pontos de restauração e cópias externas (regra 3-2-1: 3 cópias, 2 mídias, 1 fora do local).
  • Sistema de arquivos: chkdsk /f (Windows) e fsck (Linux) verificam e corrigem erros. Também: atualizações, desinstalação de programas e diretivas de segurança (regras de senha, bloqueio de conta).

Máquina virtual: crie a VM, aponte a ISO, instale o sistema e use snapshots para voltar a um estado anterior.

7. Laboratório WEB (projeto integrador)

Planejamento

O levantamento de requisitos define o que o sistema deve fazer (funcionais: cadastrar, logar; não funcionais: ser rápido, seguro). As fases: análise → design → desenvolvimento → testes → implantação. O cronograma distribui as tarefas no tempo, com responsáveis.

FaseSemanaEntrega
Análise1Requisitos e wireframes
Design2Leiaute e modelo do banco
Desenvolvimento3 a 5Front-end, back-end e banco
Testes6Correção de erros
Implantação7Publicação e apresentação

Metodologias

  • Cascata: fases em sequência, cada uma só começa quando a anterior termina; indicada quando os requisitos são estáveis.
  • Scrum (ágil): trabalho em ciclos curtos, as sprints (1 a 4 semanas), cada uma entregando uma parte funcional. Papéis: Product Owner (define prioridades), Scrum Master (facilita o processo) e equipe. Usa o backlog (lista de tarefas) e reuniões diárias curtas.
  • Kanban: quadro visual com colunas (A fazer, Fazendo, Feito) e limite de tarefas em andamento.

Ferramentas

  • Git/GitHub: controle de versão e trabalho em equipe.
  • Trello: quadro de tarefas (Kanban).
  • Editor de código: ex.: VS Code.
  • XAMPP: servidor local com Apache, MySQL e PHP; os arquivos ficam na pasta htdocs, acessados em http://localhost/projeto.
git init
git add .
git commit -m "Cadastro de alunos funcionando"
git branch -M main
git remote add origin https://github.com/usuario/projeto.git
git push -u origin main

Escolha linguagens e ambiente pelo projeto (ex.: HTML/CSS/JavaScript no front-end, PHP no back-end, MySQL no banco) e integre as camadas: o formulário (front-end) envia dados ao PHP (back-end), que grava e lê do MySQL. Em grupo, divida tarefas por afinidade, faça commits pequenos e reuniões curtas.
